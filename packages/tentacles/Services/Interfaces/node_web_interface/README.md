# node_web_interface

React web UI for the OctoBot node API, packaged as a tentacle. Built with Vite, TanStack
Router/Query, and Tailwind. The compiled bundle in `dist/` is what ships in the tentacle package.

## Requirements

Node 24 (see `.nvmrc`). Run `nvm use` before any npm command.

## Development

```bash
npm ci                    # install from the committed package-lock.json
npm run generate-client   # regenerate the typed API client from openapi.json
npm run dev               # Vite dev server
npm run build             # tsc + vite build -> dist/
npm test
```

`openapi.json` is generated by the `node_api_interface` tentacle (`python build_openapi.py`) and is
git-ignored. Generate it once before `npm run generate-client` if it is missing.

## About the `@drakkar.software/octobot-client` dependency

This tentacle is a standalone npm project. It depends on the **published**
`@drakkar.software/octobot-client` (`^0.8.1` in `package.json`), not on the copy in
`packages/client/octobot_client_ts`. It is deliberately not an npm workspace member, so that the
tentacle package exporter can `npm ci` it from any directory it gets copied to during a release.

The practical consequence: if you change the client SDK in `packages/client/octobot_client_ts`, the
web UI will not see those changes until the new version is published to npm and the `^0.8.1` range
here is bumped to match.

### Using the local client SDK while developing

When you are changing the SDK and the web UI together, point this package at the local build
instead of the published package.

First build the SDK (the web UI imports its compiled `dist/`, not its source):

```bash
cd ../../../../../packages/client/octobot_client_ts
npm run build
```

Then, from this directory, choose one method.

**`npm link` (quick, nothing to commit):**

```bash
cd ../../../../../packages/client/octobot_client_ts
npm link
cd -                                             # back to node_web_interface
npm link @drakkar.software/octobot-client
```

`npm link` only symlinks into `node_modules`, it does not touch `package.json` or
`package-lock.json`. The symlink is removed by `npm ci` and by a plain `npm install`, so re-run
`npm link @drakkar.software/octobot-client` after either. Rebuild the SDK (`npm run build` in its
directory) each time you change it. To go back to the published package, run `npm install`.

**`file:` override (persistent for a longer session):**

Add to this `package.json`, then `npm install`:

```json
"overrides": {
  "@drakkar.software/octobot-client": "file:../../../../../packages/client/octobot_client_ts"
}
```

This rewrites `package-lock.json`. Do not commit either the `overrides` block or the modified
lockfile. Revert with `git checkout package.json package-lock.json && npm ci` before committing or
building a tentacle package.

### Shipping SDK changes

To release web UI changes that rely on a new SDK API:

1. Bump the version in `packages/client/octobot_client_ts/package.json`.
2. Merge to `dev` or `master`. The `publish-npm` CI job publishes the new version to npm.
3. Bump `@drakkar.software/octobot-client` here to the new version and run `npm install` to update
   `package-lock.json`.
